# Feature: Route catalog (read)

**Branch:** `feature/route-catalog`
**Depends on:** `plans/foundation-ui-kit.md` (component library, layout, toast), `plans/auth-and-roles.md` (users, JWT guards, auth store, router guards)

## Goal

A signed-in user browses the design's 6 community routes on the Discover screen — filtering by difficulty and searching by name/description — and opens any route to see it drawn on a real Leaflet map beside its stats (distance, elevation, duration, waypoints). The `/auth` screen's right column becomes the real hero map with the floating FEATURED card. Everything is read-only: publishing is slice 4, tours are slice 5.

## Decisions (binding for this and later slices)

1. **Waypoints are a `jsonb` column** on the Route entity, not a `Waypoint` table. The path is only ever read and written whole, in order, together with its route — no per-waypoint metadata, no partial updates (slice 4 publishes the full array atomically), no cross-waypoint queries. A join table would add ordering/N+1 complexity for zero benefit, and `jsonb` matches the design's `[lat, lng][]` shape verbatim.
2. **Stats formulas live in `backend/src/routes/route-stats.ts` as pure exported functions** (no DI — trivially unit-testable). They are **not shared** with the frontend: the repo has no shared package and introducing one is out of scope. Slice 4 will port the same file to `frontend/src/lib/route-stats.ts` for the live draw sidebar, keeping the formulas byte-for-byte identical; the backend unit tests in T3 pin the exact expected outputs the port must reproduce.
3. **`GET /api/routes` and `GET /api/routes/:id` are public (no auth guard).** The unauthenticated `/auth` screen must render the real featured route (name + distance from the first route in the list), and the catalog carries no per-viewer or private data. Writes stay guarded (slice 4).
4. **Route creation is open to any authenticated user** (spec §10.1's recommendation): the nav shows "＋ Draw a route" for both roles, so slice 4's `POST /api/routes` will use `JwtAuthGuard` only, no `@Roles('GUIDE')`. Tour scheduling stays guide-only. Nothing to enforce in this slice — recorded so slice 4 follows it.
5. **List ordering: `createdAt ASC`, tiebreak `name ASC`.** Keeps the seeded design order (Medvednica first → featured), and slice-4 publishes append at the end, exactly like the prototype. The seeder inserts routes sequentially (awaited one by one) so `createdAt` ascends.
6. **The Discover screen filters client-side** over the full fetched list (one `GET /api/routes`, no params): the header count shows the *total* while the grid filters, exactly like the prototype, and filtering is instant. The `difficulty`/`search` query params are still implemented and e2e-tested — they are part of the binding contract for other consumers.
7. **Seeded users all get password `trailshare1`** (satisfies the 8+ chars / 1 digit rule) so reviewers and the tester agent can log in as e.g. `ivana@trailshare.hr`.
8. **Route-detail load failure** (404 or network): toast "Route not found" and `router.replace('/routes')`. The design has no not-found state.

## API contract

Both endpoints are **public** and return decorated DTOs. `RouteDto`:

```json
{
  "id": "9c5e…-uuid",
  "name": "Medvednica Ridge Loop",
  "description": "A steady climb through beech forest onto the ridge, then an easy return along the old logging road.",
  "difficulty": "Moderate",
  "activity": "Hiking",
  "author": { "id": "…uuid", "displayName": "Ivana Kovač" },
  "waypoints": [[45.9002, 15.9432], [45.9068, 15.9508]],
  "waypointCount": 8,
  "tourCount": 0,
  "distanceKm": 12.4,
  "distanceLabel": "12.4 km",
  "elevationM": 670,
  "elevationLabel": "670 m",
  "durationLabel": "4 h 5 min",
  "createdAt": "2026-08-13T09:00:00.000Z"
}
```

- `author` contains **exactly** `id` and `displayName` — never email, role or passwordHash.
- `waypoints` is the full ordered `[lat, lng][]` in **both** list and detail responses (the card sparkline and hero map need it; paths are tiny).
- `tourCount` is **always `0` this slice** (tours arrive in slice 5; the field ships now so the card's author row and the contract are stable).
- `distanceKm` = distance rounded to 1 decimal; `distanceLabel` = `d.toFixed(1) + ' km'`; `elevationM` = integer (multiple of 10); `elevationLabel` = `elev + ' m'`; `durationLabel` per the formula below (`"4 h 5 min"`, `"2 h"`, or `"45 min"`).

**Stats formulas (spec §8.4 — exact, binding for the slice-4 frontend port too):**

- distance: haversine sum over consecutive points, `R = 6371` km:
  `seg(a,b) = 2·R·asin(√(sin²(Δlat/2) + cos(latA)·cos(latB)·sin²(Δlon/2)))` (angles in radians).
- elevation (synthetic): `elev = round((distKm * 46 + numPoints * 12) / 10) * 10` meters.
- duration: `hrs = distKm / speed + elev / 620`, `speed = 14` when activity is `Biking`, else `4.1`. Render: `h = floor(hrs)`, `m = round((hrs − h) * 60 / 5) * 5`; if `m === 60` then `h += 1, m = 0`; label = `h ? (m ? `${h} h ${m} min` : `${h} h`) : `${m} min``. (The prototype's `activityOf()` always returns 'hike' — a prototype bug; implement properly using the route's activity.)

**Endpoints:**

- `GET /api/routes?difficulty=Easy|Moderate|Hard&search=<text>`
  - Both params optional, validated by a DTO: `difficulty` `@IsOptional() @IsEnum(RouteDifficulty)`; `search` `@IsOptional() @IsString() @MaxLength(200)`. Any other query param → 400 (global `forbidNonWhitelisted`).
  - `difficulty` = exact match; `search` = case-insensitive substring match (`ILIKE %term%`) against **name OR description**.
  - 200 → `RouteDto[]` ordered `createdAt ASC, name ASC`. Empty array when nothing matches.
- `GET /api/routes/:id`
  - `id` validated with `ParseUUIDPipe` → 400 on a non-UUID.
  - 200 → `RouteDto`; 404 `{ "message": "Route not found" }` for an unknown UUID.
